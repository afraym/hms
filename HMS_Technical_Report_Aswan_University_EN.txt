MODULE 1: PATIENT MANAGEMENT SYSTEM
===================================

Technical Implementation:
- Model: App\Models\Patient.php with HasFactory, SoftDeletes traits
- Controller: App\Http\Controllers\PatientController.php
- Database Table: patients with 20+ optimized columns
- Validation: Custom request validation with Arabic error messages
- Search: Full-text search with indexing optimization

Core Functionalities:

1.1 Patient Registration
-----------------------
Database Schema:
```sql
CREATE TABLE patients (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    full_name VARCHAR(255) NULLABLE INDEX,
    email VARCHAR(255) NULLABLE,
    phone VARCHAR(20) NULLABLE,
    national_id VARCHAR(14) NULLABLE UNIQUE,
    date_of_birth DATE NULLABLE,
    gender ENUM('male', 'female') NULLABLE,
    status ENUM('waiting', 'admitted', 'discharged', 'deceased') DEFAULT 'waiting',
    medical_id VARCHAR(255) UNIQUE NULLABLE,
    uhi_number VARCHAR(255) NULLABLE UNIQUE,
    address TEXT NULLABLE,
    governorate VARCHAR(255) NULLABLE,
    notes TEXT NULLABLE,
    blood_type VARCHAR(10) NULLABLE,
    marital_status VARCHAR(50) NULLABLE,
    occupation VARCHAR(255) NULLABLE,
    is_active BOOLEAN DEFAULT TRUE,
    created_by BIGINT UNSIGNED NULLABLE,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    deleted_at TIMESTAMP NULLABLE,
    FOREIGN KEY (created_by) REFERENCES users(id)
);
```

Advanced Features:
- Egyptian National ID validation and data extraction
- Automatic age calculation from birth date
- Duplicate patient detection algorithms
- Governorate extraction from National ID
- Gender validation against National ID
- Medical ID auto-generation with unique patterns
- Real-time form validation with AJAX

1.2 Patient Search & Retrieval
------------------------------
Search Algorithms:
- Fuzzy matching for name searches
- Multiple parameter search (ID, phone, medical ID)
- Advanced filtering with date ranges
- Pagination with configurable page sizes
- Export functionality to Excel/PDF

Performance Optimizations:
- Database indexing on searchable fields
- Query caching for frequent searches
- Lazy loading for related data
- Database query optimization with explain plans

MODULE 2: VISIT MANAGEMENT SYSTEM
=================================

Technical Implementation:
- Model: App\Models\PatientVisit.php
- Controller: App\Http\Controllers\PatientVisitController.php
- Relationships: belongsTo Patient, Department, Bed
- Events: Visit creation triggers status updates

2.1 Visit Tracking System
-------------------------
Database Schema:
```sql
CREATE TABLE patient_visits (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    patient_id BIGINT UNSIGNED NOT NULL,
    type ENUM('in', 'out') NOT NULL,
    visit_at TIMESTAMP NOT NULL,
    notes TEXT NULLABLE,
    department_id BIGINT UNSIGNED NULLABLE,
    bed_id BIGINT UNSIGNED NULLABLE,
    companion_name VARCHAR(255) NULLABLE,
    companion_relation VARCHAR(255) NULLABLE,
    companion_phone VARCHAR(20) NULLABLE,
    companion_national_id VARCHAR(14) NULLABLE,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    FOREIGN KEY (patient_id) REFERENCES patients(id) ON DELETE CASCADE,
    FOREIGN KEY (department_id) REFERENCES departments(id),
    FOREIGN KEY (bed_id) REFERENCES beds(id)
);
```

Business Logic Implementation:
- Automatic patient status updates on visit creation
- Bed allocation/deallocation automation
- Visit history tracking with timeline view
- Companion information management
- Real-time bed availability updates

MODULE 3: DEPARTMENT & BED MANAGEMENT

3.1 Department Management
------------------------
Database Schema:
```sql
CREATE TABLE departments (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

3.2 Bed Management System
-------------------------
Database Schema:
```sql
CREATE TABLE beds (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    bed_number VARCHAR(50) NOT NULL,
    room_number VARCHAR(50) NULLABLE,
    status ENUM('متاح', 'محجوز', 'صيانة') DEFAULT 'متاح',
    department_id BIGINT UNSIGNED NOT NULL,
    patient_name VARCHAR(255) NULLABLE,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);
```

Advanced Features:
- Real-time bed availability tracking
- Automatic status updates on patient admission/discharge
- Department-wise bed allocation
- Occupancy rate calculations
- Maintenance scheduling support

4.2 Role-Based Access Control
----------------------------
Database Schema:
```sql
CREATE TABLE users (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    phone VARCHAR(20) UNIQUE NULLABLE,
    email_verified_at TIMESTAMP NULLABLE,
    password VARCHAR(255) NOT NULL,
    role ENUM('admin', 'doctor', 'nurse', 'reception') DEFAULT 'reception',
    is_active BOOLEAN DEFAULT TRUE,
    remember_token VARCHAR(100) NULLABLE,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

Permission Matrix:
- Admin: Full system access
- Doctor: Patient records, visit management
- Nurse: Patient care, basic records
- Reception: Patient registration, scheduling
